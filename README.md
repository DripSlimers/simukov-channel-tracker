# Трекер каналов и соцсетей

Два трекера в одном файле. Первый - веб-версия конспекта «Источники клиентов: охота на лидов»: семь каналов лидогена, недельный ввод цифр, автосчет конверсии по нормативам, шаблоны первых сообщений и список задач. Второй - трекер соцсетей: ежедневный постинг в 4 площадки (Telegram, YouTube Shorts, Instagram, TikTok) и метрики роста.

Данные лежат в **Postgres на Supabase**, не в браузере. Вход по одноразовой ссылке на почту, свои цифры видит только владелец. Данные общие для всех устройств: отметил с телефона - видно на ноутбуке.

## Вкладки

- **Постинг** - матрица «день × площадка». Блок «Сегодня» с галочками `X/4`, стрики по каждой площадке, полные дни, клик по числу дня - заметки и ссылки на публикации.
- **Соцсети** - сводка по подписчикам и карточка на каждый аккаунт: подписчики + прирост, просмотры, мини-график роста; внутри - срезы по датам и история.
- **Неделя** - таблица «канал × показатель» за выбранную неделю. Касания, ответы, диалоги, созвоны, сделки, выручка, часы. Полоска нормы показывает, сколько касаний сделано из плана. Ниже - конверсия этой недели с оценкой.
- **Сводка** - итоги лидогена за все время, конверсия, разбивка по каналам с вердиктом и таблица по неделям.
- **Каналы** - справочник семи каналов: продукт, норма, когда пойдут сделки, что нужно для запуска, статус.
- **Шаблоны** - тексты первых сообщений по каждому каналу, с кнопкой «Скопировать».
- **Задачи** - ближайшие действия и таблица «что автоматизировать».

## Как читать вердикт канала

Считается после трех заполненных недель, по правилу из конспекта:

- **закрывать** - три недели без единого диалога
- **под вопросом** - диалоги есть, сделок нет. Проблема в оффере, не в лидогене
- **кормит** - есть сделки, показывается выручка за час

Нормативы конверсии зашиты те же, что в конспекте: касание в ответ 15-25%, ответ в диалог 50%, диалог в созвон 30-40%, созвон в сделку 25-35%, сквозная 2-5%. Ниже нижней границы - красным, выше верхней - зеленым.

## Что считать чем

- **Касание** - ты написал или позвонил первым. Не «посмотрел карточку», а именно отправил
- **Ответ** - человек хоть что-то ответил, даже «нам не надо»
- **Диалог** - разговор пошел дальше первого ответа, есть интерес
- **Созвон** - назначен и состоялся
- **Часы** - честно, включая поиск и подготовку. Без этой колонки трекер бесполезен

## Настройка Supabase

Один раз, минут на пять.

1. Завести проект на [supabase.com](https://supabase.com) (вход через GitHub). Регион - ближайший, пароль к базе можно не запоминать.
2. Открыть **SQL Editor** → New query, вставить целиком `schema.sql`, нажать Run. Затем то же самое с `schema_social.sql` (таблицы соцсетей: отметки постинга, аккаунты, срезы метрик). Если `schema.sql` уже выполнялся раньше - достаточно выполнить только `schema_social.sql`.
3. Открыть **Project Settings → API**, скопировать `Project URL` и ключ `anon public`.
4. Вписать оба значения в `config.js`, закоммитить и запушить.
5. В **Authentication → URL Configuration** прописать адрес страницы (`https://<ник>.github.io/<репозиторий>/`) в поля `Site URL` и `Redirect URLs`. Без этого ссылка из письма приведет не туда.

Готово. Открываешь страницу, вводишь почту, переходишь по ссылке из письма.

## Про ключ в открытом репозитории

`anon public` лежит в `config.js` и виден всем - так и задумано, это не секрет. Доступ к данным режет RLS из `schema.sql`: политика `auth.uid() = user_id` отдает строки только тому, кто вошел, и только его собственные. Без входа ключ не дает ничего.

Чего в репозитории быть не должно: ключ `service_role` из той же вкладки настроек. Он обходит RLS. Его не трогаем вообще.

## Локальный запуск

Просто открыть `index.html` двойным кликом не выйдет: вход по ссылке требует нормального адреса. Поднять локальный сервер:

```
python3 -m http.server 8000
```

и открыть `http://localhost:8000`. Этот адрес тоже надо добавить в `Redirect URLs` в Supabase.

## Бэкап

Данные и так в Postgres, но кнопка **Экспорт JSON** в шапке выгружает все одним файлом (недели, постинг, аккаунты, срезы) - на случай, если захочется утащить в таблицу или перенести проект. Кнопка **Импорт** заливает такой файл обратно.

## Перенос данных из старого трекера соцсетей

Старый трекер (`Claude/Ведение ТГ канала/трекер-соцсети/`) хранил все в localStorage браузера. Чтобы перенести:

1. Открыть старый трекер в том браузере, где вносились данные, нажать **Экспорт JSON**.
2. В этом трекере нажать **Импорт** и выбрать скачанный файл.

Импорт понимает оба формата: экспорт старого трекера соцсетей (`{accounts, posting}`) и полный бэкап этого трекера. Данные заливаются в Supabase, повторный импорт того же файла безопасен (upsert по ключам).
